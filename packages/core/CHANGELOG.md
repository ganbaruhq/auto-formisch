# Changelog

## Unreleased

- First version, replacing `auto-formisch-core`, `auto-formisch-json` and `auto-formisch-builder` with no compatibility layer.
- `compile` loads a version 1 Form Definition and compiles it into a three-stage root pipe usable through `~standard.validate`.
- The `text` Field Type with `required`, `requiredMessage` and the `email`, `min_length` and `max_length` Rules.
- The `number`, `boolean`, `choice`, `multi_choice` and `date` Field Types, and the `url`, `min_value`, `max_value`, `integer`, `accepted`, `min_items` and `max_items` Rules.
- The `object` and `repeater` Fields, each its own data scope, with no `required`; they always output `{}` and `[]` at least. `min_items` and `max_items` apply to a `repeater`. `FieldNode` now includes them; the single-value Fields are `ValueField`.
- Conditions: `visible` on every Component, and `disabled` and `required` as `true`, `false` or a Condition on Fields (an `object` or Repeater takes no `required`). A Condition is `all`, `any` and `not` over `{field, operator, value}` leaves, at most 8 levels deep, with `../` references. Missing Fields, operators that do not fit the Field Type, wrong values and cycles through `visible` or `disabled` are load errors. An Inactive Field is not validated, not in the output and reads as empty; an Inactive `object` or Repeater outputs `{}` or `[]` and skips its Rules. `compiled.conditions` is the evaluator `prep` uses, for Renderers.
- Load errors are thrown together as a `DefinitionError` of `{message, path}`.
- `setRequiredMessage(message, lang?)` and `deleteRequiredMessage(lang?)`: a required error resolves through `requiredMessage`, then `setRequiredMessage`, then `Required`, and never shows the internal value. Other messages go through Valibot, with the Definition's `message` first.
- The Fluent Builder: Valibot-style functions and pipes (`text`, `number`, `boolean`, `choice`, `multiChoice`, `date`, `object`, `repeater`, `section`, `grid`, `tabs`, `tab`, `content`; Rules such as `email` and `minLength`; metadata such as `label` and `defaultValue`; `visible`, `required` and `disabled`; the Condition helpers `all`, `any`, `not`, `eq`, `neq`, `isIn`, `notIn`, `gt`, `gte`, `lt`, `lte`, `contains`, `isEmpty` and `notEmpty`). `form()` returns plain Definition data checked by the same loader as JSON, and `compile` infers its output type; a pipe item that doesn't apply to its Field fails to compile.
- A value Field's `default`, checked on load for being non-empty, of the Field's type and through its Rules. It stays out of the schema.
- A Repeater's `default`: a non-empty list of rows, each checked against the template and the whole list through the Repeater's Rules. The Fluent Builder's `defaultValue` takes it on a `repeater`.
- `compiled.defaults`: the input a new form starts with, a fresh copy on every read. `compiled.normalize(record)` and `compiled.newRow(repeater)` serve Renderers: the starting input for an edited record (full shape, keys without a Field dropped, values of the wrong JavaScript type emptied with a warning, a custom Field Type's included), and a new Repeater row from its template's defaults.
- `lock(compiled, values)` Locks single-value Fields by data path for one form instance. Their values replace the input's before Conditions run, beat `initialInput` and `default`, and skip `required` and Rules; a Condition can still make them Inactive. Invalid paths, values of the wrong JavaScript type (only the type: a choice since removed still locks) and locking twice throw a `LockError` of `{message, path}`. `compiled.locked` lists the Locked Fields for Renderers.
- Wizards: the root has `components` or root `pages`, never both. A `page` (label, description, columns, visible) sits only in `pages`, and all Pages share the root data scope. A Wizard compiles to one whole-form schema, so a server validates it like any form; a hidden Page makes its Fields Inactive. `page()` and `wizard()` write Pages in the Fluent Builder. `shownPages`, `pageOf` and `pageErrors` let a Renderer navigate and a server check one Page. `FormDefinition` is now `SinglePageDefinition | WizardDefinition`, and `TypedDefinition` a type alias.
- Custom Field Types (`defineFieldType`) and Rules (`defineRule`), passed explicitly to `compile` and `form` as `{ fieldTypes, rules }`, with no global registry. A custom type holds one JSON value checked by its sync, validate-only schema, with flat strict options, no `rules`, errors on the Field path and a `conditionAs` row; a custom Rule applies to built-in value Field Types. Both are typed in the Fluent Builder. Invalid or duplicate names, built-in names and keys, and async schemas or checks throw a `TypeError` at registration; an unregistered type or Rule throws on load; custom code that throws while validating propagates. New exports: `defineFieldType`, `defineRule`, `CustomField`, `LoadOptions`, `FieldType`, `Rule`, `InferFieldValue`, `InferFieldNode` and their helper types.
- A JSON Schema (draft-07) for format version 1 ships at `schema/v1.json`, with `$id` `https://cdn.jsdelivr.net/npm/@auto-formisch/core/schema/v1.json`, for a Definition's `$schema`. It describes every built-in `type`, Rule, Condition and `default`, and takes any other `type` or Rule name loosely as a custom one; the loader stays the one judge.
- `validateForm(compiled, input, { lang })` validates in the language of one request and returns `{ value }` or `{ errors }` of `{ message, path }`, the shape `onSubmit` may return. New exports `validateForm`, `ValidateOptions` and `ValidationResult`.
- A Field's Rules run in Definition order and stop at the first that fails, so a custom Rule after a failed `max_length` never sees the overlong value.
